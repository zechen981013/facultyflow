# Python 项目与 Java 项目之间是怎么通信的？

> 本文对应任务交付物第 9 项：写个总结文档，讲下 python 项目和 java 项目之间是怎么通信的。
> 2026-08-29

---

## 一、一句话总结

**Python 项目通过 HTTP + JSON + Token 的方式，以"模拟浏览器"的身份去调用服务端 Java 系统对外开放的 REST 接口（API），拿到数据后再做计算、展示和发薪。**

```
Python 前台(浏览器页面)
     │  ① 用户在页面上操作（登录、看图表、点发薪）
     ▼
Python 后台 (FastAPI :5000)      ← 本任务自己写的
     │  ② 用 requests 库发 HTTP 请求
     ▼
服务端 Java 后端 (Spring Boot :8080)  ← 服务端提供的系统
     │  ③ Java 读写自己的 MySQL，消费 RabbitMQ 发工资
     ▼
MySQL / RabbitMQ
```

---

## 二、为什么是"HTTP 调用"而不是直接连数据库

HTTP（超文本传输协议）是 Web 世界的通用语言。任何一个系统只要对外开放了接口（URL），任何语言都能调用——**Python 调 Java 的接口，跟浏览器访问网页本质上是同一件事**：

| | 浏览器访问网页 | Python 调 Java 接口 |
| --- | --- | --- |
| 动作 | 输入网址 → 回车 | 代码里发 HTTP 请求 |
| 本质 | HTTP GET/POST | HTTP GET/POST（requests 库） |
| 拿回什么 | HTML 页面 | JSON 数据 |

所以 Python 不需要知道 Java 内部怎么写的（Spring MVC、JPA、MySQL 都不用管），只需要知道"哪个 URL、传什么参数、返回什么 JSON"。这就是**接口（API）解耦**的思想。

> 对比：如果 Python 直接连服务端的 MySQL 数据库（JDBC 直连），就等于绕过了系统的业务规则和权限校验，还会造成两边都要维护数据库连接，不优雅也不安全。所以标准做法是**后台调后台的接口**。

## 三、调用流程（完整走一遍）

以"Python 后台拿 2026 年 7 月考勤数据"为例：

### 第 1 步：登录拿 Token（通行证）

```python
import requests

BASE = "http://localhost:8080"                      # 服务端 Java 系统的地址
r = requests.post(f"{BASE}/api/auth/login",
                  json={"username": "wangfang", "password": "123456"})
data = r.json()                                      # {'code':0, 'data':{'token':'6b9380d2...'}}
token = data["data"]["token"]                        # 拿到通行证
```

**为什么需要登录？** HTTP 是无状态的，服务器默认"不认识你"。登录成功后，Java 系统发一串 token（类似门禁卡），之后的每个请求都带上它，Java 才能知道"你是谁、有没有权限"。

### 第 2 步：带 Token 调业务接口

```python
r = requests.get(f"{BASE}/api/attendance/month",
                 params={"year": 2026, "month": 7},
                 headers={"Authorization": f"Bearer {token}"})   # 带上门禁卡
employees = r.json()["data"]["employees"]            # 21 名员工的考勤数据
```

### 第 3 步：Python 处理数据

- 用 `salary.py` 里的规则计算每个人工资（固定薪水扣款 / 销售提成 / 个税）
- 汇总实发总额、分部门平均薪水
- 生成折线图、饼图所需数据

### 第 4 步：发工资（Python → Java → RabbitMQ）

```python
# 先查 Java 系统里的工资单（带 id 和状态）
records = requests.get(f"{BASE}/api/salary/list", params={"year": 2026, "month": 7},
                       headers=headers).json()["data"]
# 把要发的人的 id 交给 Java 的发放接口
requests.post(f"{BASE}/api/salary/pay", json={"ids": [3, 7]}, headers=headers)
```

Java 后端收到请求后**不直接打钱**，而是把发放请求丢进 RabbitMQ 队列，消费者按自己的节奏逐条处理——这就是"削峰填谷"，模拟 20000 人同时发工资不崩。

## 四、通信协议与数据格式细节

### 4.1 请求

| 要素 | 约定 |
| --- | --- |
| 协议 | HTTP（本机 http://localhost:8080） |
| 方法 | GET（查询）/ POST（操作） |
| 内容类型 | `Content-Type: application/json` |
| 认证 | 请求头 `Authorization: Bearer <token>` |

### 4.2 响应（Java 系统统一格式）

```json
{
  "code": 0,          // 0 成功；非 0 失败
  "message": "success",
  "data": { ... }     // 业务数据
}
```

### 4.3 接口清单

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | /api/auth/login | 登录拿 token |
| GET | /api/attendance/month | 全员考勤 |
| POST | /api/salary/calculate | Java 侧算工资 |
| GET | /api/salary/list | 工资单列表 |
| GET | /api/salary/statistics | 统计 |
| POST | /api/salary/pay | 发工资（入队） |
| POST | /api/salary/pay/simulate | 模拟高并发 |

### 4.4 共用一张用户表

考勤服务和 Python 系统**共用 `employee` 表**，Python 端**不建用户表**，登录就是调 Java 的 `/api/auth/login`。登录返回里有 `departmentName`，Python 后台校验只有 `财务部` 能登录进来发工资、看图表。

## 五、本项目中 Python 的分层（对照三层架构）

```
analytics/python_app/
├── app.py            # controller 层：对外提供 /api/xxx 给 Python 前端
├── salary.py         # service 层：工资计算业务
├── java_client.py    # dao/api 层：封装 HTTP 调用服务端 Java 接口 ← 相当于"数据访问层"
├── mcp_server.py     # FastMCP 工具：把"发工资"封装成 MCP 工具
└── static/           # Python 前端页面（登录、图表、发薪）
```

注意：这里的"dao 层"访问的不是 SQL，而是服务端的 HTTP 接口——**服务端的接口就是我们的"数据库"**。

---

## 六、总结

1. **通信方式**：HTTP + JSON + Token（REST 风格接口调用）。
2. **为什么能通信**：HTTP 是跨语言通用的协议，Java 开接口，任何语言都能调。
3. **Python 的职责**：把服务端的 Java 系统当作数据源，负责"取数 → 算工资 → 展示 → 发薪"。
4. **安全**：登录走服务端的用户表，Python 侧只放行财务部，真正发钱的动作仍在 Java 侧 + RabbitMQ 完成。
